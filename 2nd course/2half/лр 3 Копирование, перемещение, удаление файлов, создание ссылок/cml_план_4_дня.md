## День 1. Разбор аргументов командной строки

### Теория

Когда программа запускается как `./cml -h 123 456.txt`, операционная система передаёт в `main` два параметра:

- `argc` — количество аргументов (включая имя самой программы). Для примера выше `argc = 4`.
- `argv` — массив строк (`char *argv[]`), где:
  - `argv[0]` — имя программы,
  - `argv[1]`, `argv[2]`... — то, что ввёл пользователь.

Задача первого дня — понять, **сколько аргументов передано и что это за аргументы**, и решить: правильный это вызов или нет.

Правила из задания:
- Обязательных параметров (исходный файл и результирующий файл) должно быть ровно 2.
- Опция (`-h`, `-l`, `-m`) необязательна, и её может быть максимум 1 (если она есть, то это дополнительный, третий, аргумент).
- Значит, всего аргументов (не считая `argv[0]`) может быть либо 2 (без опции), либо 3 (опция + 2 файла).
- Если аргументов меньше 2 или больше 3 — ошибка.
- Если аргументов 3, но первый из них — не `-h`, `-l` или `-m` — ошибка (неизвестная опция).

Обратите внимание на пример из задания: `cml -h -l -x` — это **верный** синтаксис! Почему? Потому что здесь ровно 2 "обязательных параметра" — это строки `-l` и `-x`, а `-h` — опция. Программа не обязана проверять, что "файлы" реально похожи на имена файлов — она просто проверяет количество и опцию. Реальная проверка существования файла и его типа будет на 2 дне.

Функции/конструкции, которые понадобятся:
- `strcmp(a, b)` — сравнение строк. Возвращает 0, если строки равны.
- `fprintf(stderr, "...")` — вывод сообщения об ошибке в поток ошибок (а не `printf`, который пишет в обычный вывод). Это хороший тон: ошибки должны идти в `stderr`.
- `return 1;` из `main` — сигнал операционной системе, что программа завершилась с ошибкой (по договорённости 0 = успех, не 0 = ошибка).

Как объяснить преподавателю своими словами: "Программа сначала смотрит, сколько всего слов пользователь написал после имени программы. Если их не 2 и не 3 — сразу ошибка. Если их 3, значит первое слово должно быть одной из трёх опций, иначе тоже ошибка. Всё, дальше первый и второй/третий 'файл' мы просто запоминаем в переменные, а проверять их существование будем позже."

### Практика

Сегодня пишем только разбор аргументов и вывод справки. Файл `cml.c`:

```c
#include <stdio.h>
#include <string.h>

void print_help(void)
{
    printf("Использование: cml [-h|-l|-m] исходный_файл результирующий_файл\n");
    printf("Опции:\n");
    printf("  -h  создать жесткую ссылку\n");
    printf("  -l  создать символическую ссылку\n");
    printf("  -m  переместить/переименовать файл\n");
    printf("Без опции файл будет скопирован.\n");
}

int main(int argc, char *argv[])
{
    int h_flag = 0, l_flag = 0, m_flag = 0;
    char *source_file = NULL;
    char *target_file = NULL;

    /* argc всегда включает имя программы, поэтому реальное
       количество аргументов пользователя = argc - 1 */
    int user_args = argc - 1;

    if (user_args != 2 && user_args != 3)
    {
        fprintf(stderr, "Ошибка: неверное количество аргументов\n");
        print_help();
        return 1;
    }

    if (user_args == 3)
    {
        if (strcmp(argv[1], "-h") == 0)
            h_flag = 1;
        else if (strcmp(argv[1], "-l") == 0)
            l_flag = 1;
        else if (strcmp(argv[1], "-m") == 0)
            m_flag = 1;
        else
        {
            fprintf(stderr, "Ошибка: неизвестная опция '%s'\n", argv[1]);
            print_help();
            return 1;
        }
        source_file = argv[2];
        target_file = argv[3];
    }
    else
    {
        source_file = argv[1];
        target_file = argv[2];
    }

    /* Пока просто проверяем, что всё разобралось правильно */
    printf("h=%d l=%d m=%d\n", h_flag, l_flag, m_flag);
    printf("source=%s target=%s\n", source_file, target_file);

    return 0;
}
```

Проверка (компиляция и тесты):

```bash
gcc -Wall -o cml cml.c

./cml -h 1 2          # верно: h=1, source=1, target=2
./cml 123 456.txt      # верно: без опций
./cml -h -l -x         # верно: h=1, source=-l, target=-x (это ожидаемо по заданию!)
./cml -h -l            # неверно: только 1 аргумент после опции
./cml -k 123 456.txt   # неверно: неизвестная опция
./cml 1 2 3 4          # неверно: слишком много аргументов
./cml                  # неверно: аргументов нет вообще
./cml -l               # неверно: только опция, файлов нет
```

Если все эти проверки дают ожидаемый результат — день 1 готов.

## День 2. Проверка исходного и результирующего файлов

### Теория

Теперь, когда мы знаем имена файлов, нужно проверить:
1. Существует ли исходный файл?
2. Является ли он "обычным файлом" (regular file) или ссылкой?
3. Если результирующий файл существует — является ли он обычным файлом или ссылкой?

Для этого в Си есть функция `stat()` из `<sys/stat.h>`:

```c
struct stat st;
int rc = stat("имя_файла", &st);
```

- Если `stat` вернул `-1` — файла не существует (или нет прав на доступ). Это можно проверить через `errno`, но для нашего задания достаточно смотреть на возвращаемое значение.
- Если `stat` вернул `0` — файл существует, и структура `st` заполнена информацией о нём, в частности полем `st.st_mode`, которое хранит тип файла и права доступа.

Чтобы узнать **тип** файла, используются специальные макросы:
- `S_ISREG(st.st_mode)` — истина, если это обычный файл.
- `S_ISLNK(st.st_mode)` — истина, если это символическая ссылка.
- (есть ещё `S_ISDIR` для директорий и т.д., но нам они не нужны)

Важный нюанс: `stat()` **следует** по символическим ссылкам, то есть если файл — это ссылка на обычный файл, `stat()` покажет тип конечного файла (обычный файл), а не самой ссылки. Чтобы увидеть именно ссылку, есть функция `lstat()` — она не переходит по ссылке, а смотрит на сам объект. В примере из задания используется `stat()`, поэтому ссылка, которая указывает на обычный файл, будет опознана как `S_ISREG`. Это нормально для учебного задания, но если хотите быть точнее — можно проверять и `lstat()` тоже (объяснено в конце как усложнение).

Логика проверки:
1. Если исходный файл не существует (`stat` вернул -1) — ошибка, стоп.
2. Если исходный файл существует, но не `S_ISREG` и не `S_ISLNK` — ошибка, стоп (например, это директория).
3. Проверяем результирующий файл через `stat`:
   - Если он существует, но не `S_ISREG`/`S_ISLNK` — ошибка, стоп.
   - Если он существует и является обычным файлом/ссылкой — запоминаем этот факт (пригодится в 4 дне для запроса подтверждения).
   - Если не существует — тоже нормально, идём дальше.

Как объяснить преподавателю: "Функция `stat` — это способ спросить у операционной системы информацию о файле: существует ли он и какого он типа. Мы оборачиваем это в свою функцию `is_regular_file`, которая возвращает 1, если файл существует и является обычным файлом или ссылкой, и 0 в любом другом случае (не существует, директория, спецфайл и т.д.)."

### Практика

Добавляем к коду из дня 1 функцию проверки и логику:

```c
#include <stdio.h>
#include <string.h>
#include <sys/stat.h>

void print_help(void)
{
    printf("Использование: cml [-h|-l|-m] исходный_файл результирующий_файл\n");
}

/* Возвращает 1, если файл существует и является обычным файлом или ссылкой */
int is_regular_file(const char *path)
{
    struct stat st;
    if (stat(path, &st) != 0)
        return 0; /* файла не существует или нет доступа */

    return S_ISREG(st.st_mode) || S_ISLNK(st.st_mode);
}

/* Возвращает 1, если файл вообще существует (неважно, какого типа) */
int file_exists(const char *path)
{
    struct stat st;
    return stat(path, &st) == 0;
}

int main(int argc, char *argv[])
{
    int h_flag = 0, l_flag = 0, m_flag = 0;
    char *source_file = NULL;
    char *target_file = NULL;
    int user_args = argc - 1;

    if (user_args != 2 && user_args != 3)
    {
        fprintf(stderr, "Ошибка: неверное количество аргументов\n");
        print_help();
        return 1;
    }

    if (user_args == 3)
    {
        if (strcmp(argv[1], "-h") == 0) h_flag = 1;
        else if (strcmp(argv[1], "-l") == 0) l_flag = 1;
        else if (strcmp(argv[1], "-m") == 0) m_flag = 1;
        else
        {
            fprintf(stderr, "Ошибка: неизвестная опция '%s'\n", argv[1]);
            print_help();
            return 1;
        }
        source_file = argv[2];
        target_file = argv[3];
    }
    else
    {
        source_file = argv[1];
        target_file = argv[2];
    }

    /* Проверка исходного файла */
    if (!file_exists(source_file))
    {
        fprintf(stderr, "Ошибка: исходный файл '%s' не существует\n", source_file);
        return 1;
    }
    if (!is_regular_file(source_file))
    {
        fprintf(stderr, "Ошибка: исходный файл '%s' не является обычным файлом или ссылкой\n", source_file);
        return 1;
    }

    /* Проверка результирующего файла */
    int target_exists = file_exists(target_file);
    if (target_exists && !is_regular_file(target_file))
    {
        fprintf(stderr, "Ошибка: результирующий файл '%s' существует, но не является обычным файлом или ссылкой\n", target_file);
        return 1;
    }

    printf("Проверки пройдены. target_exists=%d\n", target_exists);
    return 0;
}
```

Проверка:

```bash
gcc -Wall -o cml cml.c

touch a.txt
mkdir somedir

./cml a.txt b.txt        # "Проверки пройдены. target_exists=0"
./cml no_such_file.txt b.txt   # "исходный файл ... не существует"
./cml somedir b.txt       # "не является обычным файлом"
touch b.txt
./cml a.txt b.txt         # "target_exists=1"
./cml a.txt somedir       # "результирующий файл ... не является обычным файлом"
```

## День 3. Сами операции: копирование, перемещение, ссылки

### Теория

Теперь, когда файлы проверены, нужно реализовать 4 варианта действия.

**1. Копирование (по умолчанию, если нет опций)**

Копирование вручную делается через низкоуровневые функции `<fcntl.h>` и `<unistd.h>`:
- `open(path, flags, mode)` — открывает файл, возвращает файловый дескриптор (число) или -1 при ошибке.
  - Для чтения: `O_RDONLY`.
  - Для записи в новый/существующий файл: `O_WRONLY | O_CREAT | O_TRUNC` (создать, если нет; обрезать до 0, если есть), плюс права `0644`.
- `read(fd, buffer, size)` — читает до `size` байт в буфер, возвращает сколько реально прочитано (0 — конец файла).
- `write(fd, buffer, n)` — записывает `n` байт из буфера.
- `close(fd)` — закрывает дескриптор (важно не забывать, иначе "утечка" дескрипторов).

Идея копирования: читаем файл кусками (например, по 4096 байт) в цикле, пока `read` не вернёт 0 или ошибку, и каждый раз записываем прочитанное в целевой файл.

**2. Перемещение / переименование (`-m`)**

Тут всё просто — одна функция:
```c
rename(source_file, target_file);
```
Она либо переименовывает файл в той же файловой системе, либо физически перемещает. Возвращает 0 при успехе, -1 при ошибке.

**3. Жёсткая ссылка (`-h`)**

```c
link(source_file, target_file);
```
Создаёт новую "запись в каталоге", которая указывает на тот же самый файл на диске (тот же inode). После этого у файла как бы два имени, и оба указывают на одни и те же данные. Возвращает 0/-1.

**4. Символическая ссылка (`-l`)**

```c
symlink(source_file, target_file);
```
Создаёт отдельный маленький файл-указатель, который просто хранит путь `source_file` как текст. Если удалить исходный файл, символическая ссылка "сломается" (в отличие от жёсткой ссылки). Возвращает 0/-1.

Во всех этих функциях при ошибке хорошо использовать `perror("текст")` — она допечатывает к вашему тексту причину ошибки от операционной системы (берётся из `errno`).

Как объяснить преподавателю: "У нас есть 4 варианта поведения, и каждому соответствует своя системная функция: копирование — это ручное чтение/запись через `open/read/write/close`, потому что в Си нет готовой функции 'скопировать файл'. А перемещение, жёсткая и символическая ссылки — это уже готовые системные вызовы `rename`, `link`, `symlink`, каждый из которых просто перекладывает работу на операционную систему."

### Практика

Добавляем функции для операций (пока без запроса подтверждения — это будет в 4 дне):

```c
#include <stdio.h>
#include <string.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>

#define BUFFER_SIZE 4096

int copy_file(const char *src, const char *dst)
{
    int src_fd = open(src, O_RDONLY);
    if (src_fd == -1)
    {
        perror("Ошибка открытия исходного файла");
        return 0;
    }

    int dst_fd = open(dst, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (dst_fd == -1)
    {
        perror("Ошибка открытия результирующего файла");
        close(src_fd);
        return 0;
    }

    char buffer[BUFFER_SIZE];
    ssize_t bytes_read;
    while ((bytes_read = read(src_fd, buffer, BUFFER_SIZE)) > 0)
    {
        ssize_t bytes_written = write(dst_fd, buffer, bytes_read);
        if (bytes_written != bytes_read)
        {
            perror("Ошибка записи");
            close(src_fd);
            close(dst_fd);
            return 0;
        }
    }

    close(src_fd);
    close(dst_fd);
    return 1;
}

int main(void)
{
    /* Небольшой тест функций по отдельности, без разбора аргументов */
    if (copy_file("a.txt", "copy_of_a.txt"))
        printf("Копирование успешно\n");

    if (rename("copy_of_a.txt", "renamed.txt") == 0)
        printf("Переименование успешно\n");
    else
        perror("rename");

    if (link("a.txt", "hardlink.txt") == 0)
        printf("Жесткая ссылка создана\n");
    else
        perror("link");

    if (symlink("a.txt", "symlink.txt") == 0)
        printf("Символическая ссылка создана\n");
    else
        perror("symlink");

    return 0;
}
```

Проверка:

```bash
gcc -Wall -o test_ops test_ops.c
touch a.txt
echo "привет" > a.txt
./test_ops

ls -l a.txt copy_of_a.txt renamed.txt hardlink.txt symlink.txt
cat renamed.txt      # должно показать "привет"
ls -li a.txt hardlink.txt   # у обоих одинаковый inode (первое число)
ls -l symlink.txt    # должно показывать "symlink.txt -> a.txt"
```

Сегодня главное — понять и проверить, что каждая из 4 функций отдельно работает правильно. Завтра соберём всё вместе.

## День 4. Подтверждение перезаписи и сборка полной программы

### Теория

Осталась последняя часть логики: что делать, если результирующий файл **уже существует**.

По заданию: нужно спросить пользователя разрешение, и:
- если "да" — удалить старый файл и выполнить операцию как обычно;
- если "нет" — остановиться, ничего не делая.

Для чтения ответа пользователя используется `scanf`:
```c
char response;
scanf(" %c", &response);
```

Важная деталь: пробел перед `%c` (`" %c"`) — это не опечатка! Он говорит `scanf` пропустить все "пробельные" символы (пробелы, табуляции, и главное — символ новой строки `\n`), которые могли остаться во входном потоке от предыдущего ввода. Без этого пробела программа может "случайно" прочитать символ перевода строки вместо реального ответа пользователя.

Для удаления файла используется:
```c
unlink(target_file);
```
Она удаляет запись о файле из файловой системы (для обычного файла это удаляет и данные, если это было последнее имя файла / ссылка на него).

Общий план `main`, собирающий все 4 дня вместе:

1. Разобрать аргументы (день 1).
2. Проверить исходный файл (день 2).
3. Проверить результирующий файл на тип, если существует (день 2).
4. Если результирующий файл существует — спросить разрешение (день 4), при отказе — выйти; при согласии — `unlink`.
5. Выполнить нужную операцию: копирование/перемещение/жёсткая ссылка/симлинк (день 3).

Как объяснить преподавателю: "Мы спрашиваем пользователя через `scanf`, используя пробел перед `%c`, чтобы не словить случайный символ конца строки из предыдущего ввода. Если ответ — 'y' или 'Y', удаляем старый файл функцией `unlink` и дальше работаем так, как будто файла не было."

### Практика

Полная финальная программа `cml.c`:

```c
#include <stdio.h>
#include <string.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>

#define BUFFER_SIZE 4096

void print_help(void)
{
    printf("Использование: cml [-h|-l|-m] исходный_файл результирующий_файл\n");
    printf("Опции:\n");
    printf("  -h  создать жесткую ссылку\n");
    printf("  -l  создать символическую ссылку\n");
    printf("  -m  переместить/переименовать файл\n");
    printf("Без опции файл будет скопирован.\n");
}

int file_exists(const char *path)
{
    struct stat st;
    return stat(path, &st) == 0;
}

int is_regular_file(const char *path)
{
    struct stat st;
    if (stat(path, &st) != 0)
        return 0;
    return S_ISREG(st.st_mode) || S_ISLNK(st.st_mode);
}

int copy_file(const char *src, const char *dst)
{
    int src_fd = open(src, O_RDONLY);
    if (src_fd == -1)
    {
        perror("Ошибка открытия исходного файла");
        return 0;
    }
    int dst_fd = open(dst, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (dst_fd == -1)
    {
        perror("Ошибка открытия результирующего файла");
        close(src_fd);
        return 0;
    }
    char buffer[BUFFER_SIZE];
    ssize_t bytes_read;
    while ((bytes_read = read(src_fd, buffer, BUFFER_SIZE)) > 0)
    {
        if (write(dst_fd, buffer, bytes_read) != bytes_read)
        {
            perror("Ошибка записи");
            close(src_fd);
            close(dst_fd);
            return 0;
        }
    }
    close(src_fd);
    close(dst_fd);
    return 1;
}

int main(int argc, char *argv[])
{
    int h_flag = 0, l_flag = 0, m_flag = 0;
    char *source_file = NULL;
    char *target_file = NULL;
    int user_args = argc - 1;

    /* --- День 1: разбор аргументов --- */
    if (user_args != 2 && user_args != 3)
    {
        fprintf(stderr, "Ошибка: неверное количество аргументов\n");
        print_help();
        return 1;
    }

    if (user_args == 3)
    {
        if (strcmp(argv[1], "-h") == 0) h_flag = 1;
        else if (strcmp(argv[1], "-l") == 0) l_flag = 1;
        else if (strcmp(argv[1], "-m") == 0) m_flag = 1;
        else
        {
            fprintf(stderr, "Ошибка: неизвестная опция '%s'\n", argv[1]);
            print_help();
            return 1;
        }
        source_file = argv[2];
        target_file = argv[3];
    }
    else
    {
        source_file = argv[1];
        target_file = argv[2];
    }

    /* --- День 2: проверка файлов --- */
    if (!file_exists(source_file))
    {
        fprintf(stderr, "Ошибка: исходный файл '%s' не существует\n", source_file);
        return 1;
    }
    if (!is_regular_file(source_file))
    {
        fprintf(stderr, "Ошибка: исходный файл '%s' не является обычным файлом или ссылкой\n", source_file);
        return 1;
    }

    int target_exists = file_exists(target_file);
    if (target_exists && !is_regular_file(target_file))
    {
        fprintf(stderr, "Ошибка: результирующий файл '%s' существует, но не является обычным файлом или ссылкой\n", target_file);
        return 1;
    }

    /* --- День 4: подтверждение перезаписи --- */
    if (target_exists)
    {
        printf("Результирующий файл '%s' существует. Удалить и продолжить? (y/n): ", target_file);
        char response;
        scanf(" %c", &response);

        if (response != 'y' && response != 'Y')
        {
            printf("Операция отменена пользователем\n");
            return 0;
        }

        if (unlink(target_file) != 0)
        {
            perror("Ошибка удаления результирующего файла");
            return 1;
        }
    }

    /* --- День 3: выполнение операции --- */
    if (h_flag)
    {
        if (link(source_file, target_file) != 0)
        {
            perror("Ошибка создания жесткой ссылки");
            return 1;
        }
        printf("Жесткая ссылка создана: '%s' -> '%s'\n", target_file, source_file);
    }
    else if (l_flag)
    {
        if (symlink(source_file, target_file) != 0)
        {
            perror("Ошибка создания символической ссылки");
            return 1;
        }
        printf("Символическая ссылка создана: '%s' -> '%s'\n", target_file, source_file);
    }
    else if (m_flag)
    {
        if (rename(source_file, target_file) != 0)
        {
            perror("Ошибка перемещения файла");
            return 1;
        }
        printf("Файл перемещен: '%s' -> '%s'\n", source_file, target_file);
    }
    else
    {
        if (!copy_file(source_file, target_file))
            return 1;
        printf("Файл скопирован: '%s' -> '%s'\n", source_file, target_file);
    }

    return 0;
}
```

## Возможные проблемы

- **Забыли пробел в `scanf(" %c", ...)`.** Без пробела символ `\n`, оставшийся во входном буфере, может быть прочитан как "ответ", и программа решит, что пользователь отказался, хотя он ничего не успел ввести.
- **`stat` вместо `lstat`.** `stat` следует по символическим ссылкам до конечного файла, поэтому симлинк на директорию не будет отловлен функцией `is_regular_file` как ошибка (он "превратится" в директорию, и `S_ISREG`/`S_ISLNK` будут ложны — тут на самом деле сработает как надо). Но если хотите различать "это симлинк" от "это обычный файл" именно по внешнему виду файла, а не по тому, на что он указывает, — нужен `lstat`. Для этого задания `stat` подходит, но будьте готовы объяснить разницу преподавателю.
- **Забыли закрыть файловые дескрипторы** (`close`) при ошибке в середине копирования — это утечка ресурсов. В примере выше это учтено, но легко забыть при доработках.
- **Права доступа при копировании.** В примере права нового файла всегда `0644`, то есть права исходного файла не сохраняются. Если преподаватель попросит сохранять права — надо взять `st_mode` исходного файла (через `stat`) и передать его в `open` вместо `0644`, или дополнительно вызвать `chmod`.
- **`rename` между разными файловыми системами.** Системный вызов `rename` может завершиться ошибкой `EXDEV`, если исходный и результирующий файлы находятся на разных смонтированных разделах/дисках. Простая реализация (как в этом задании) не обрабатывает такой случай отдельно — она просто выведет ошибку через `perror`. Полноценные `mv` в такой ситуации сами делают копирование + удаление, но это уже сложнее и не требуется по заданию.
- **Компиляция под Windows.** Функции `link`, `symlink`, `unlink`, `stat` — это POSIX-функции, они работают в Linux/macOS. Под Windows (без WSL или MinGW с поддержкой POSIX) собрать эту программу не получится. Проверяйте задание в Linux-окружении.
- **Тестирование `-m` "портит" тестовые файлы.** После `./cml -m a.txt d.txt`, файла `a.txt` больше не будет (он переименован в `d.txt`). Не забывайте пересоздавать тестовые файлы (`touch`/`echo`) перед повторными тестами.
- **Одинаковые исходный и результирующий файл.** Задание явно этого не требует проверять, но если преподаватель спросит "а что если source и target — один и тот же файл?", будьте готовы сказать, что сейчас это не обрабатывается отдельно (например, `copy_file` с одинаковым src/dst через `O_TRUNC` обнулит файл), и это можно упомянуть как известное ограничение/возможное улучшение.
